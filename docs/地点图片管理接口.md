# 地点图片管理接口

## 目的

地点图片由后台显式管理，不再依赖小程序启动、重新编译或用户登录触发。

当前接口运行在云函数 `parking` 中，所有写操作必须通过管理员 OPENID 白名单校验。

## 新增/替换图片

调用云函数：

```json
{
  "action": "admin-add-place-image",
  "data": {
    "place_id": 1,
    "asset_path": "assets/place-images/北京路步行街.jpg",
    "cloud_path": "place-images/v5/北京路步行街.jpg",
    "image_url": "原图来源地址",
    "image_alt": "北京路步行街地点实景图",
    "image_credit": "图片署名",
    "image_source_url": "来源页面地址"
  }
}
```

说明：

- `asset_path` 必须位于云函数包的 `assets/place-images/` 目录内。
- `cloud_path` 必须位于云存储 `place-images/` 目录内。
- `image_url`、`image_credit`、`image_source_url` 用于记录来源和版权信息。
- 新图上传成功后才更新 `p_places`；数据库更新失败会回滚新图。
- 数据库更新成功后，才尝试删除该地点原来的 `image_file_id`。
- 如果旧 fileID 仍被其他地点引用，则跳过删除并在返回值中标记原因。

## 删除图片

调用云函数：

```json
{
  "action": "admin-delete-place-image",
  "data": {
    "place_id": 1
  }
}
```

说明：

- 接口只根据 `place_id` 读取数据库中的当前 `image_file_id`，不接受外部 fileID，避免误删其他文件。
- 会清空 `p_places` 中的图片字段，并删除不再被其他地点引用的云存储文件。
- 接口返回 `old_file_deleted` 和 `old_file_delete_reason`，用于核验清理结果。

## 标准操作顺序

换图时由后台按以下顺序显式调用：

1. 调用 `admin-delete-place-image` 删除旧图。
2. 调用 `admin-add-place-image` 上传新图并写入新 fileID。

如果希望详情页始终有图，也可以只调用 `admin-add-place-image`，它会在新图写库成功后自动清理旧图。

## 图片规格

- 横屏优先。
- 宽度建议 1024px。
- 单张图片不超过 100KB。
- 必须保留来源页、作者/机构和授权说明。
