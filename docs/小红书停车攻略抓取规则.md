# 小红书停车攻略抓取规则

## 适用范围

本规则用于按地点采集小红书公开可见的停车攻略，并将结果整理为停车场维度的待审核数据。采集只读取登录后页面中实际可见的文字、标题、作者、时间、互动信息和链接，不绕过验证码、登录限制、风控或权限限制。采集与整理必须分为两个阶段：先保存原始页面数据，再从本地原始数据整理攻略。

## 执行流程

### 0. 默认自动执行方式

用户下达一个地点范围或清单任务后，默认一次性完成“搜索抓取→原始数据落盘→按规则筛选→停车场维度整理→收费与评论复核→停车点坐标核验→入库格式校验”的完整流程，不需要用户逐个地点或逐个停车场再次下令。各地点之间按顺序自动执行，并在对话中汇报阶段性进度。

只有遇到登录失效、验证码/安全限制、页面明确要求人工验证，或删除范围存在歧义时才暂停并请求用户处理；普通的加载慢、单个笔记打不开、单个停车点暂时找不到坐标，不得作为停止整批任务或逐点等待确认的理由，应按跳过、重试、替代检索和批量标记方式继续执行。

### 0.1 原始数据优先落盘

1. 每次打开搜索结果页，先保存一份搜索页原始 JSON；每次打开笔记详情页后，无论成功、内容不完整或出现安全限制，都尽量保存一份独立的详情页原始 JSON。
2. 原始文件只保存页面上实际可见的文字、标题、链接、发布时间/互动信息（页面有展示时）以及采集时间、搜索词、排序方式、笔记排名和加载状态；不保存 Cookie、密码、浏览器身份信息、图片或视频文件。
3. 每条笔记使用独立文件，文件名至少包含采集时间、搜索词、排序排名和笔记 ID；汇总文件只作为索引和进度记录，不替代独立原始文件。
4. 后续过滤、收费提取、评论筛选、停车场合并和坐标整理只读取本地原始 JSON，除非原始文件缺失且用户明确允许重新访问，否则不得为整理结果重复打开同一笔记。
5. 原始数据与整理数据分目录保存。原始数据是待处理材料，不得直接导入正式数据库；整理阶段输出待审核的入库格式，并保留原始文件路径用于追溯。
6. 遇到验证码、安全限制、登录墙或“访问链接异常”时，保存当前可见状态和错误页面内容后停止继续访问该地点，等待冷却或人工处理，不尝试绕过限制。

### 1. 搜索

以用户提供的地点生成搜索词：

```text
{地点} 停车攻略
```

必要时可补充同义搜索词，例如“{地点} 停车场”“{地点} 自驾停车”，但每个搜索词单独记录，后续统一去重。

### 2. 按收藏量筛选和阅读

1. 读取搜索结果中的笔记卡片。
2. 点击页面右上角“筛选”，在“排序依据”中选择“最多收藏”，等待结果刷新后再读取卡片。
3. 依次打开“最多收藏”排序后的笔记，读取完符合条件的笔记后，整理出所有有实质内容且不重复的停车攻略，不限制为 3 条。同一停车点的多条笔记只合并为一条，不重复收录。
4. 以下情况跳过当前笔记，继续读取下一条：
   - 视频笔记；
   - 正文基本没有停车信息；
   - 只有标题、图片文字无法可靠读取，且正文没有可用补充；
   - 内容明显与目标地点无关；
   - 没有任何可确认的收费标准。没有收费标准的停车点不收录。
5. 如果页面没有“最多收藏”选项或点击后没有成功刷新，不得把点赞量、评论量或搜索结果顺序冒充收藏量。此时记录 `收藏量筛选未生效`，并在结果中说明实际采用的排序依据。
6. 最多读取 10 条有实质正文的笔记；读取到第 10 条后停止继续读取，保留在这 10 条笔记中发现的全部合格且不重复停车攻略，并说明实际读取数量。若前 10 条中已有多条合格攻略，也全部保留，不因数量超过 3 条而截断。

### 3. 停车信息过滤

只保留与停车直接相关的内容，过滤以下内容：

- 景点游玩路线、拍照攻略、历史介绍；
- 餐厅、饮品、购物和消费推荐；
- 与停车无关的交通、地铁和旅游体验；
- 与目标地点无明确关系的泛化经验。

停车场到目的地的步行路线、步行距离、轮渡/接驳方式、入口方向、车型限制和节假日排队情况，如果直接影响停车决策，应保留在停车备注中。例如“停车后步行约300米到目的地”应整理进攻略。与停车无关的游玩路线、景点介绍和餐饮信息仍需过滤。

评论区信息也必须进行停车相关性筛选：

- 评论中提到路窄、进出不便、中午或节假日容易堵车、排队等候、车位紧张、入口封闭、缴费后限时驶离等情况，只要与停车决策直接相关，就应提炼后放入停车备注。
- 评论中的收费变动、临时管制或优惠失效信息，应注明可识别的月份或时间，例如“2月有反馈按4元/30分钟计费，请现场留意停车场收费标准”，不得直接当成当前统一收费标准。
- 评论内容与停车无关、缺少地点和时间背景、明显是闲聊或无法确认事实的，不纳入攻略；互相矛盾的评论要降低可信度，并提醒以现场为准。
- 对评论进行简洁改写，只保留停车决策需要的信息，不展示作者姓名，不复制整段评论。

### 4. 信息整理

每条有效信息只整理以下字段：

| 字段 | 处理要求 |
|---|---|
| 停车场名称 | 统一名称，去除表情和无意义前后缀 |
| 地址或导航词 | 保留停车场地址、入口或推荐导航词 |
| 经纬度 | 优先为每个收录停车场补充可用于导航的 `lng`、`lat` 坐标，不能使用目标地点中心点代替；确实无法核验时允许暂为空，但必须标记待补充 |
| 收费明细 | 提取按小时、半小时、免费时长、封顶价、优惠券等 |
| 车型限制 | 记录机械车位、限重、SUV/新能源限制等 |
| 停车备注 | 简要改写实用提示，如入口、排队、停车后到目的地的步行距离、步行路线和接驳方式 |
| 可信度 | 官方/现场明确说明为高；单个公开笔记为中；评论冲突或时间较旧为低 |
| 来源记录 | 保留原笔记链接、标题、作者、发布时间和采集时间，供审核追溯 |

同一停车场的多条信息合并为一条；收费冲突不强行平均或择一覆盖，保留不同来源的差异并标记“待现场核实”。

经纬度和导航要求：

- 每个准备入库的停车场都必须自动执行坐标补充流程，使用项目现有地图导航接口兼容的坐标体系，字段名为 `lng` 和 `lat`。坐标补充不是可选的后置工作，也不能因为候选整理完成就省略。
- 坐标补充应在整批停车点上连续执行，不逐个等待用户确认。对每个停车点依次尝试：停车场名称检索、地址/导航词检索、入口名称检索、地图详情核对；同一停车场的多个候选坐标要结合地址、道路和入口进行消歧。
- 坐标应对应停车场本身或实际入口，不能直接使用沙面、商场或其他目的地的中心坐标代替；同名停车场要结合地址、入口和周边道路核对。
- 坐标可通过地图检索、地址定位或其他可核验的公开地图信息补充，并在内部记录坐标来源和核验时间；无法可靠匹配时不得猜测坐标。
- 坐标缺失或无法确认时，必须先完成上述批量检索和合理重试，再将该条标记为“待补充”；不得猜测坐标，也不得使用目标地点或附近其他停车场的坐标代替。少量确实无法核验的记录可以先进入正式停车攻略，但必须保留待补充状态，不得让整批任务停在“等待用户逐条确认”。
- 有效坐标记录入库前检查 `lng`、`lat` 非空且数值有效；暂缺坐标的记录必须标记 `coordinate_status: "待补充"`、`navigation_available: false`，页面应隐藏或禁用该停车场的导航按钮，并提示暂无停车场坐标。
- 导航按钮必须使用该停车场自己的坐标跳转，而不是使用地点详情页的坐标；后续找到可靠坐标后，回填坐标并恢复导航能力。

坐标批处理完成后，必须输出坐标统计：停车点总数、已核验数量、待补充数量、未通过消歧数量及失败原因。未完成坐标批处理统计前，不得声称停车攻略已达到最终入库条件。

收费信息的处理要求：

- `收费明细`只填写正文或页面中明确出现的收费标准、免费时长、封顶价和优惠规则；没有收费标准的笔记或停车点不收录。
- 原文明确写出具体数字时，必须按原数值准确输出，不得无理由添加“约”。例如原文写“5元/小时”，整理后就写“5元/小时”；原文写“封顶30元”，就写“封顶30元”。
- 只有原文明确使用“大约、左右、约”等模糊表述，或不同时间/不同记录存在收费冲突时，才可以保留“约”或在`停车备注`中说明不确定性；不能用“约”笼统掩盖尚未核对的问题。
- 单次停车的实际支付金额与收费标准要分开表达。若只有“停车3小时10分钟、实付17.25元”这类记录，应写成“实付记录：17.25元（停车3小时10分钟）”，不得改写成“收费17.25元”或推算出未经证实的小时价。
- 评论区出现的涨价、实付金额或临时变化，不得直接当作当前正式收费标准，也不得把多条评论拼成一个未经证实的价格区间。
- 这类评论只能放在`停车备注`中，并尽量注明月份，例如“2月有反馈称已调整为4元/30分钟，请现场留意停车场收费标准”。

备注排版要求：

- 备注内容较多或同时包含多个主题时，使用分点换行，统一采用“数字+前缀”的格式，避免堆成一段长文本。
- 推荐格式：

```text
1、收费：XXX
2、路线：XXX
3、注意：XXX
```

- `收费`写收费标准和优惠提醒，`路线`写停车后步行/接驳指引，`注意`写路窄、拥堵、排队、车型限制、入口和临时变化等风险。
- 单一主题且内容很短时可以写成一句话；需要分点时，前缀顺序优先使用“收费→路线→注意”，每点保持简洁。

面向用户展示时，以停车场为中心直接描述整理后的信息，例如“北京路天河城地下停车场：会员优惠可兑换停车券，停车约 5 小时曾出现 10～15 元的实际支付情况，机械车位封顶约 80 元/天”。不得写成“某博主称”“有笔记提到”或展示作者姓名。

上述是展示口径，不代表信息已被官方或现场核验。内部待审核记录必须继续保留来源链接、标题、作者、发布时间和采集时间；不得将公开笔记整理内容宣称为官方信息、平台自有数据或自行实测结果。

## 改写和版权边界

- 只提取停车事实并进行简短摘要，不复制整段正文、评论、图片或视频。
- 停车备注使用自己的简洁表述，避免与原文逐句相同。
- 不下载或保存原帖图片、视频；正式展示时只保留必要的来源链接。
- “改写”不等于自动获得版权许可；如需大规模商业使用，应另行确认平台规则和授权要求。

## 输出和入库规则

先写入待审核数据，不直接覆盖正式停车场数据。每条记录至少包含：

```json
{
  "place": "地点名称",
  "parking_name": "停车场名称",
  "address": "地址或导航词",
  "lng": 113.2644,
  "lat": 23.1252,
  "coordinate_status": "已核验",
  "navigation_available": true,
  "fee_detail": "收费摘要",
  "parking_notes": "停车备注",
  "confidence": "medium",
  "source_url": "原笔记链接",
  "source_title": "原笔记标题",
  "source_author": "作者",
  "source_published_at": "发布时间",
  "captured_at": "采集时间",
  "conflict_flag": false
}
```

同一停车场经过人工审核后，再更新正式数据库中的停车场、收费规则和攻略提示。
