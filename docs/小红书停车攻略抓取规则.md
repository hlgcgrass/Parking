# 小红书停车攻略抓取规则

## 一、职责范围

本文件只规定小红书笔记的搜索、筛选、访问和原始数据保存方式。

笔记内容的清洗、评论提取、收费整理、停车场合并、定位补充、攻略改写、入库校验和数据库写入，统一按照以下文件执行：

`docs/小红书攻略数据整理规则.md`

抓取阶段不得提前把笔记整理成停车场数据，也不得直接修改或写入正式数据库。

## 二、合规边界

1. 只读取登录后页面中实际可见的公开内容。
2. 不绕过登录限制、验证码、安全验证、风控或访问权限。
3. 不使用隐藏自动化、指纹伪装、代理轮换、签名破解、接口模拟或其他规避平台检测的手段。
4. 遇到验证码、风险提示、访问受限或页面要求人工验证时，保存当前可见状态和错误信息，停止当前地点的抓取。
5. 不下载或保存笔记图片、视频等媒体文件；只保存后续整理所需的可见文字和页面元数据。

## 三、执行流程

### 3.1 接收地点任务

1. 按用户提供的地点清单逐个处理。
2. 地点之间串行抓取，不同时打开多个地点的搜索结果页。
3. 每个地点完成搜索页记录和笔记原始数据保存后，至少等待 10 秒再搜索下一个地点；搜索页加载失败等提前结束路径也要等待后再进入下一个地点。
4. 普通的加载慢、单条笔记打不开或单条数据不完整，不停止整批任务；记录状态后继续下一条。

### 3.2 生成搜索词

默认搜索：

```text
{地点} 停车攻略
```

必要时可以补充以下搜索词，每个搜索词都要单独记录：

```text
{地点} 停车场
{地点} 自驾停车
```

后续整理阶段再对不同搜索词得到的笔记进行去重，抓取阶段不合并内容。

### 3.3 筛选图文和排序

1. 打开搜索结果页并等待页面内容稳定。
2. 点击“筛选”，在“笔记类型”中选择“图文”。
3. 选择“图文”后至少等待 3 秒，确认筛选结果刷新，再在“排序依据”中选择“最多点赞”。
4. 每次筛选或排序后都等待页面刷新，确认筛选条件已经生效。
5. 只有确认“图文”和“最多点赞”均已生效后，才打开结果笔记。
6. 如果筛选或排序没有生效，只保存搜索页状态，不把当前结果冒充为图文或最多点赞结果。

### 3.4 搜索结果相关性初筛

1. 在“图文”和“最多点赞”均确认生效后，先只读取搜索结果卡片中实际可见的标题、地点和互动信息，不打开笔记详情。
2. 卡片标题或可见文字必须明确提到目标地点或已登记别名/简称。别名应覆盖常见简称、官方旧称和同一交通枢纽的关联名称，例如“广州北站”同时识别“广州北”“花都站”“广州城际花都站”；只出现沙面、南沙、北京路等其他地点且未提到目标地点的结果，标记为“地点不匹配”并跳过。
3. 在地点一致的结果中，再按停车相关词进行轻量评分。停车场、停车费、收费、车位、车库、地库、停车入口、停车攻略等词优先；游玩、门票、拍照、亲子、美食、夜景等词降权。
4. 相关性评分和地点过滤只用于决定是否打开候选笔记，不改写或删除搜索页原始内容；候选及跳过原因一并保存。

### 3.5 打开笔记

1. 按“最多点赞”排序后的当前显示顺序，从通过相关性和地点初筛的候选中逐条打开图文笔记。
2. 打开详情页后等待页面稳定，保留足够的阅读时间；默认详情页读取停留 5 秒。
3. 该停留用于页面加载、内容读取和降低访问压力，不用于伪装真人或规避平台检测。
4. 每条笔记访问完成后，先点击详情卡片左上角的关闭按钮；确认详情卡片已消失、地址回到搜索结果页且结果卡片恢复后，再等待至少 5 秒，才打开下一条；不要直接用历史返回或在详情卡片仍存在时切换。
5. 最多读取 5 条通过初筛且有实质内容的图文笔记，并记录实际读取数量。
6. 不以“停车场数量”为抓取上限；在已读取的笔记中发现的内容全部保留到原始数据，是否合格由数据整理规则判断。

## 四、原始数据保存

### 4.1 搜索页原始记录

每次打开搜索结果页，都保存一份搜索页原始 JSON，至少记录：

- 地点名称；
- 搜索词；
- 筛选条件及是否生效；
- 排序条件及是否生效；
- 页面采集时间；
- 搜索结果卡片中实际可见的标题、链接、笔记 ID、发布时间和收藏/点赞/评论等互动数据；
- 页面加载状态、异常信息和可见错误提示。

### 4.2 笔记详情原始记录

每条打开过的笔记使用独立 JSON 保存，无论页面完整、部分加载、打不开或触发安全限制，都应尽量保存当前可见状态。

详情原始 JSON 至少记录：

- 地点名称和搜索词；
- 搜索结果排名；
- 笔记 ID、链接、标题；
- 页面实际可见的正文文字；
- 页面实际可见的作者、发布时间和互动数据；
- 页面实际可见的评论区文字；
- 页面实际可见的作者回复文字；
- 采集时间；
- 页面加载状态和错误信息。

评论区和作者回复在抓取阶段只按页面原文保存，不判断是否有用、不改写、不归纳；后续是否保留及如何改写，按照数据整理规则执行。

### 4.3 文件和目录

1. 每条笔记必须保存独立文件，文件名至少包含采集时间、搜索词、结果排名和笔记 ID。
2. 搜索页原始 JSON、笔记详情 JSON、抓取进度和错误记录分开保存。
3. 原始数据与整理数据分目录保存。
4. 汇总文件只用于索引和进度记录，不替代独立详情文件。
5. 原始 JSON 只作为数据整理输入，不直接导入数据库。
6. 原始数据缺失时，是否重新访问由用户另行决定；整理阶段默认只读取本地原始 JSON。

## 五、跳过和停止规则

### 5.1 跳过单条笔记

以下情况可以记录原因后跳过当前笔记，继续下一条：

- 页面明确不是图文笔记；
- 内容无法打开且已保存错误状态；
- 页面内容与搜索地点明显无关；
- 页面没有可读取的有效内容；
- 当前笔记重复出现在已保存的搜索结果中。

抓取阶段不判断收费是否完整，也不因为“没有收费标准”而删除笔记；是否符合停车攻略入库要求由数据整理规则判断。

### 5.2 停止当前地点

出现以下情况时，保存当前状态并停止当前地点，不尝试绕过限制：

- 登录失效；
- 验证码或安全验证；
- 操作频繁、访问受限或风险提示；
- 页面明确要求人工确认；
- 连续出现无法访问的异常状态。

停止一个地点后，是否继续其他地点，按照当前任务安全状态决定，并在结果中说明。

## 六、抓取结果交付

抓取阶段只交付以下内容：

1. 搜索页原始 JSON；
2. 每条笔记的详情原始 JSON；
3. 抓取清单和实际读取数量；
4. 筛选、排序和加载状态；
5. 跳过、异常和停止原因；
6. 原始文件目录或文件索引。

抓取阶段不得交付或生成以下结果作为最终数据：

- 停车场清单；
- 收费明细；
- 攻略正文；
- 评论总结；
- 地点或停车场经纬度；
- 入库 JSON；
- 数据库新增、删除或更新操作。

## 七、与数据整理规则的衔接

抓取完成后，将本地原始 JSON 交给：

`docs/小红书攻略数据整理规则.md`

后续所有清洗、信息提取、评论处理、文本改写、地点和停车场定位、总结生成及入库操作，均以数据整理规则为准，不在本文件重复定义。

## 八、版权和展示边界

1. 原始数据仅保存后续整理所需的页面可见文字和元数据，不保存图片、视频等媒体文件。
2. 原始文本不直接作为小程序最终展示内容。
3. 面向用户的内容必须经过数据整理规则规定的筛选和改写，并保留必要的内部来源记录。
4. 如需大规模商业使用，应另行确认平台规则和授权要求。
